# 探索与目标索取

状态：已确认产品设计基线。

> 本页与已接受的[自由向量移动、导航、迷雾与目标索取协议](movement-navigation-protocol.md)共同定义空间执行。weighted Basic Theta*、fixed-point position、观察和 fog destination 已 Ready for implementation，但尚未写入产品代码。

## 世界知识

世界知识属于玩家世界状态，与确定性地形生成结果分离。

| 层 | 内容 | 更新条件 |
|---|---|---|
| 基础地图 | 已揭露空间的地形与可通行信息 | 初始揭示或权威观察事件 |
| 当前可见目标 | 已知资源、敌人和地点的当前有效状态 | 观察、耗尽、死亡、重生或其他内容状态变化 |
| 特殊发现 | 地标、资源类型、敌人类型和叙事线索的首次发现记录 | 首次满足发现条件 |

任务系统不得读取迷雾后的目标。不可达、耗尽或死亡的目标仍可保留在世界知识中，但在恢复有效前不属于可索取目标。

产品不定义可完成的全局世界边界，因此不计算或展示全局探索完成百分比。Accepted gameplay tile coordinate 范围是 `[-2^31, 2^31-1]`，连续 `WorldPoint` 使用每 tile `1024` nav units 的精确整数编码；不能由此宣称无限坐标精度。

## 探索技能

`探索` 经验只来自：

- 首次揭露一个未知世界单元；
- 首次发现地标；
- 首次发现资源类型；
- 首次发现敌人类型；
- 首次发现叙事线索。

同一世界单元和同一发现记录只能结算一次。重复经过、移动本身、待机、不可达和失败不提供探索经验。

首个端到端版本中，`探索` 等级唯一的能力效果是提高有效观察半径。它不提高移动速度、潜行能力、发现品质或扫描品质。

自由向量协议把 reveal unit 定为 terrain tile，观察圆半径定为 `min(13, 4 + floor((ExplorationLevel - 1)/10)) tiles`。观察发生于新存档起点、跨入新 tile、path endpoint 和 action target arrival。初始揭示不发 XP；后续每个首次揭示 tile 发 `1 Exploration XP`。单次观察使用事件开始时等级，升级后的半径从下一次观察生效。这些数值是 Accepted 首轮平衡基线；不能用移动距离或现实时间替代首次揭示结算。

[碎片叙事与线索簿](narrative-cluebook.md)把叙事首次发现组织为 `Fact`、`Relation`、`Insight` 和 `Lead`。正式 ID 和内容表由专项在编码前补齐；重复发现不能重复授予探索经验。

## 目标候选

一个目标只有同时满足以下条件时才能进入候选集：

1. 位于已揭露世界知识中。
2. 类型与当前 `TaskIntent` 匹配。
3. 当前处于有效状态。
4. 任务级永久等级、已装备工具、材料等前置条件满足。
5. 从角色当前位置通过已揭示空间到达。

不可达目标从当前候选集中排除，但不从世界知识删除。资源耗尽和敌人死亡后，在各自内容规则规定的时间重生；重生前不属于有效目标。

敌人地图知识使用跨重生稳定的 `placement_id`。一次遭遇、潜行和战斗使用 `placement_id + spawn_cycle` 构成的 `encounter_instance_id`；目标索取不能把旧 spawn identity 当作当前有效敌人。

## 最近目标

系统按 weighted Basic Theta* 返回的最低 `routeCost` 选择最近目标，不按直线距离，也不声称找到连续空间数学全局最短路径。route cost 使用 BigInt/有理数 boundary 参数、`ceilSqrt` subleg length 和 terrain factor 的 Accepted 算术契约。

路径成本相同时按稳定 `placement_id` 选择。不得使用容器遍历顺序或随机选择。

选定目标在仍有效时保持稳定，不因途中发现更近目标而改道。目标失效、一次行动或击杀完成、任务替换，或自动探索发现合格目标时，系统才重新索取。上述精确算法和保持规则属于 Accepted 移动协议。

## 自动探索

采集、伐木、采矿或狩猎任务没有可索取目标，以及材料已满足的 production task 没有已知可达 compatible station 时：

1. 保留原 `TaskIntent` 和已完成数量。
2. 进入 `自动探索` 执行状态。
3. 选择最近可达迷雾边界。
4. 向该边界移动，并只根据新揭露信息更新候选集。
5. 一旦发现合格资源/敌人或 compatible station，立即终止自动探索并重新规划到该目标的路径。

系统不能读取迷雾后的目标，也不能为了等待已知目标重生而放弃仍可执行的自动探索。若没有可达目标且没有可达 frontier，则进入 `NoReachableTargetOrFrontier`。资源或敌人重生后可以唤醒该等待并重新索取。

Production 必须先验证 recipe/level/equipment 和材料。缺材料时原地等待，不为材料自动探索；只有材料足够且 recipe 需要 station 时，才允许为 compatible station 自动探索。Handcraft recipe 不索取 station。

自动探索是为当前任务服务的执行状态，不是新任务，不改变任务优先级和技能成长方向。

## 主动探索任务

### 指定目的地

自由向量协议规定以下 Accepted 语义：

- 目的地是连续 `WorldPoint`。已揭示、角色圆可站立且可达时，按权威任意角 path 前往；抵达后任务完成并待机。
- 未揭示或通行性未知的目的地不是已知 path。系统只能沿已揭示空间逐步探索，不能读取迷雾后的 terrain 或 target。
- 已揭示且不可通行的目的地进入 `DestinationUnreachable`。
- 已揭示且可通行、但当前没有已知路径时，只要存在可达 frontier 就继续探索；frontier 用尽后才报告不可达。
- 地图点击或 `Lead` 只预填探索 `TaskIntent`；玩家确认后统一通过 `SetTask` 提交。

### 未指定目的地

- 角色持续选择最小 `(routeCost, y, x)` frontier；导航点是 frontier tile center。
- 任务不会自动完成，直到玩家取消或替换。
- 没有可达 frontier 时进入 `NoReachableTargetOrFrontier`。

## 与潜行和战斗的边界

探索只负责世界知识和目标索取。敌人侦测、潜行经验和强制战斗由[战斗与潜行](combat-stealth.md)处理。

- `探索` 等级不承担潜行职责。
- 当前狩猎目标跳过避战判定并进入强制战斗。
- 其他敌人发现角色后可以中断探索或前往目标状态；战斗结束后按当时唯一 `TaskIntent`、目标和 prerequisites 决定从精确交战位置继续 path，或重算。
- forced combat 暂停 current motion leg；玩家死亡则取消 route/action，并在精确死亡位置复活后从头重评任务和路径。

## UI

地图必须区分基础地图、当前可见目标和特殊发现。目标不可达、已耗尽、已死亡或等待重生时，应显示其知识状态，但不能把它作为当前可索取目标。

详细显示要求见[玩法 UI](gameplay-ui.md#地图)。

## 验收标准

- 任务系统不能返回迷雾后的目标。
- 候选目标必须同时满足已知、类型匹配、当前有效、任务前置条件和可达。
- 最近目标按当前路径成本确定，不按直线距离。
- 相同路径成本不会因遍历顺序、帧率或随机流产生不同选择。
- 不可达或暂时无效目标保留世界知识，但从候选集排除。
- 资源耗尽和敌人死亡后，在重生前不能被重新索取。
- 没有目标时进入自动探索，而不是等待原目标重生。
- 自动探索发现合格目标后立即让位给原任务。
- 没有可达目标和迷雾边界时原地待机，并显示原因。
- 重复揭露或发现不重复提供探索经验。
- 无限世界不显示全局探索完成率。
