# 玩法 UI

状态：已确认产品设计基线。

UI 必须解释玩家意图、当前执行状态、结算结果和停止原因。它不能把未实现功能显示为可用，也不能用逐帧日志掩盖状态语义。

[玩法界面信息架构](gameplay-information-architecture.md)已将 map-first shell、drawer、响应式布局和 Worker/UI contract 确认为首个切片的现行设计。该 Accepted 规范尚未实现。

## 任务设置器

任务设置器显示：

- 任务类别；
- 目标类型或具体配方；
- 可选数量，并明确“留空 = 持续”；
- 目标或配方的永久基础等级要求；
- 工具要求；
- 材料要求；
- 提交后将替换当前任务的提示。

`SetTask` 立即原子结束旧任务实例、丢弃旧任务计数并替换唯一 `TaskIntent`。`CancelTask` 立即清除它。若角色正在战斗，当前 `CombatState` 继续；UI 必须同时显示唯一的新意图和“当前战斗结束或复活后执行”。界面不得显示 pending task、第二个 active intent 或 queue。

系统不得默认勾选自动购买、自动换装、自动消耗品、任务队列或其他首版排除行为。

## 主状态

主状态同时显示：

```text
玩家意图 + 当前执行状态 + 任务进度 + 停止/等待原因
```

示例格式：

```text
狩猎狼 7/20｜前往目标
生产铁剑 3/10｜等待条件：缺少铁锭
采矿铜矿 持续｜自动探索：寻找可达铜矿
```

示例只说明信息结构，不声明首批敌人、资源或配方内容。

状态名称至少覆盖：`索取目标`、`前往目标`、`执行行动`、`自动探索`、`战斗`、`等待复活`、`等待条件`、`已完成`。

若任务在战斗中被替换，主状态必须同时显示当前战斗和已经成为唯一 `TaskIntent` 的新意图，不能让玩家误以为替换任务会逃离战斗，也不能把新意图表示成 pending queue。

## 技能页

每项已发布技能显示：

- 技能名称；
- 永久基础等级；
- 当前累计经验；
- 当前等级进度和升至下一级所需经验；
- 下一主要里程碑；
- 已解锁内容；
- 下一个明确内容要求；
- 技能等级、装备和临时效果各自提供的加成来源。

技能页不显示虚拟等级。装备或临时效果不能把显示的基础等级改写为可绕过准入的“有效等级”。

首版不显示职业、技能点、天赋树、洗点、训练焦点、目标熟练度或未发布技能占位。

## 地图

地图必须区分：

- 基础地图；
- 当前可见目标；
- 特殊发现。

目标状态至少能区分当前有效、不可达、耗尽/死亡、等待重生。迷雾后的目标不能显示或参与任务索取。

无限世界不显示全局探索完成率。可以显示局部已知信息，但不得把 viewport、当前 cache 或已揭露区域误写为世界总量。

## 战斗与复活

战斗状态显示当前交战对象、生命和其他已定义战斗资源、限时效果及其剩余世界时间。装备入口在战斗中必须禁用，并说明只能在非战斗状态更换。

死亡后显示复活等待、精确死亡 `WorldPoint` 和复活后将重新评估的唯一任务意图。死亡期间 HP 和其他战斗资源保持死亡状态，不显示自然恢复；复活事件一次性设置 `max_hp` 和首版其他战斗资源默认值。首轮 `60s` 与复活后的 `5s RevivalGrace` 都是 Accepted 首轮平衡基线；界面必须说明 grace 只阻止非狩猎目标敌人强制遭遇，不得把它显示为 buff、无敌或战后恢复期。界面不得暗示营地传送、尸体跑、物品、货币、经验、耐久或其他额外损失。

## 离线回归报告

离线回归报告字段见[离线推进](offline-progression.md#回归报告)。报告必须把实际经过时间、有效推进时间和停止原因分开显示。

## 事件记录

事件记录以结算事件为主，包括：

- 任务创建、替换、取消和完成；
- 资源或生产行动完成；
- 首次揭露和首次发现；
- 遭遇判定结果；
- 击杀、掉落和经验包；
- 死亡与复活；
- 等级提升和内容解锁；
- 等待或停止原因。

不输出逐帧移动、逐次攻击、逐次受伤或无状态变化的轮询日志。

## Accepted UI 范围

[玩法界面信息架构](gameplay-information-architecture.md)统一组织 gameplay shell、地图、任务、技能、Inventory/Equipment、Journal、offline report 和 System UI。[物品与装备系统](item-equipment.md#ui)、[碎片叙事与线索簿](narrative-cluebook.md#线索簿-ui)和[存档与离线结算协议](save-offline-protocol.md#ui)分别定义各领域的 Accepted 信息边界。具体 Worker 字段、视觉 token 和可访问性 fixture 必须在编码前补齐并写入对应专项文档；这些实现工作不改变已确认的信息架构。

界面允许玩家点击 fog coordinate 来预填连续 `WorldPoint` 探索目的地，但不能读取迷雾后路径或目标。完整自由向量 frontier 语义见[移动协议](movement-navigation-protocol.md#指定探索目的地)。最终任务变更只能由玩家提交 `SetTask`。

## 验收标准

- UI 始终能解释角色为何移动、战斗、探索、等待或停止。
- 玩家意图和当前执行状态同时可见，且不会相互覆盖。
- 任务设置器准确表达目标、数量和要求；留空数量含义明确。
- 技能页分开显示永久基础等级和各加成来源。
- 未实现或明确排除功能不显示为可用入口。
- 地图不会泄露迷雾后目标，也不显示无限世界全局完成率。
- 地图可以显示任意角自动路线，但不提供手动角色移动；UI 不重新计算 Theta*、route cost、ETA、观察或遭遇结果。
- 战斗中不能更换装备，且 UI 给出原因。
- 事件记录以有效结算和状态变化为粒度，不产生逐帧噪声。
