# 自动任务

状态：已确认产品设计基线。

## 目标与控制边界

玩家用一个活动任务表达当前意图。玩家决定任务类别和目标；系统只负责索取合格目标、寻路、执行行动和处理中断。

系统不得为了提高效率、补足材料、平衡技能、等待重生或遵循推荐路线而自行更换任务类别、目标类型、装备或策略。

[碎片叙事与线索簿](narrative-cluebook.md)允许现有玩法事件产生知识和可选地图线索，但不允许叙事发现自动创建、替换或重排任务。

[自由向量移动、导航、迷雾与目标索取](movement-navigation-protocol.md)已经 Accepted。weighted Basic Theta*、fixed-point motion、观察与遭遇事件已 Ready for implementation；规定 fixtures 属于实现验收。

## 任务类别

首个端到端版本固定包含 `6` 类任务。`狩猎` 和 `生产` 是任务类别，不是技能。

| 任务类别 | 必填目标 | 可选数量 | 技能结算 |
|---|---|---|---|
| `探索` | 无；可选地图目的地 | 不适用 | `探索` |
| `采集` | 资源类型 | 数量 | `采集` |
| `伐木` | 木材资源类型 | 数量 | `伐木` |
| `采矿` | 矿石或石材类型 | 数量 | `采矿` |
| `生产` | 具体配方 | 数量 | 由配方决定 `锻造`、`工艺` 或未来生产技能 |
| `狩猎` | 敌人类型 | 击杀数量 | 按实际战斗方式；首版为 `近战` |

采集、伐木、采矿、生产和狩猎必须指定目标类型。数量留空表示持续执行，直到玩家取消或替换任务。

探索可以指定地图目的地。目的地尚未揭示时，系统只能沿已揭示 frontier 增量寻路，不能读取迷雾后的 terrain 或 target；精确规则见 Accepted 移动协议。指定目的地时，抵达后完成；未指定时持续前往最近可达 frontier。

## 单一活动任务

- 同时只存在一个活动任务，不设计任务队列。
- `SetTask` 原子结束旧任务实例，并立即把唯一 `TaskIntent` 替换为新任务。
- `CancelTask` 原子结束旧任务实例，并立即清除唯一 `TaskIntent`；若没有更高优先级状态，角色进入待机。
- 替换或取消会丢弃旧任务实例的已完成数量。
- 已获得物品、已完成击杀、已结算经验和世界知识不回滚。
- 战斗、死亡和自动探索不会结束仍然有效的任务，也不会重置其任务计数。

在战斗中调用 `SetTask` 或 `CancelTask` 仍立即替换或清除唯一 `TaskIntent`，并立即丢弃旧 task counter。当前 `CombatState` 作为更高优先级 interrupt 继续，不能借此逃离战斗。战斗结束或角色复活后，系统执行当时唯一的 `TaskIntent`；若已清除，则待机。系统不保存 pending task，不创建第二个 active intent，也不形成 queue。

## 数量与完成

- 有数量任务按实际目标产出或实际目标击杀计数。
- 计数达到或超过目标数量后，任务完成，角色原地待机。
- 完成后不自动选择下一任务。
- 额外产量按实际数量增加物品和任务计数，但不增加该次技能基础经验。
- 非目标敌人击杀提供正常经验和掉落，但不增加狩猎计数。

一次行动产出超过剩余任务数量时，保留完整实际产物，任务计数记入实际产量并标记完成；不得截断产物或凭空调整产量。

## 执行优先级

系统按以下固定优先级决定当前执行状态：

1. 死亡与复活。
2. 已触发的强制战斗。
3. 玩家指定任务。
4. 为当前任务服务的自动探索。
5. 原地待机。

高优先级状态可以中断低优先级执行，但不能静默改写 `TaskIntent`。任务意图与执行状态必须分离。

## 执行状态

首个端到端版本至少支持：

| 状态 | 含义 |
|---|---|
| `索取目标` | 根据当前任务在已知世界中筛选目标 |
| `前往目标` | 按当前路径移动到选定目标 |
| `执行行动` | 执行资源、生产或接触目标行动 |
| `自动探索` | 为原任务寻找新的已知目标 |
| `战斗` | 处理已触发的强制战斗 |
| `等待复活` | 死亡后等待复活截止时间 |
| `等待条件` | 缺料、无可达目标/边界或其他明确条件不足 |
| `已完成` | 有数量任务达到目标，或有目的地探索抵达 |

UI 应同时显示玩家意图和当前执行状态，不能只显示其中之一。详细要求见[玩法 UI](gameplay-ui.md)。

## 生产周期

生产任务按一个具体配方执行：

- 一个配方周期不可部分产出。
- 周期完成时一次性消耗材料，并一次性产生完整输出。
- 强制战斗打断生产时，暂停当前周期的剩余时间。战斗结束后，只有 `TaskIntent` 和 action prerequisites 都未改变，才继续同一周期。
- 取消或替换生产任务时，取消当前周期；未完成周期不消耗材料，也不产生输出或经验。
- 周期完整输出超过剩余任务数量时，保留完整产物并完成任务。
- 材料、工具和永久基础等级均满足时，首版生产必定成功；不设置随机失败或品质等级。

## 生产评估与工作站

每次评估 production task 时，按以下顺序处理：

1. 验证 recipe、永久技能等级和 required equipment。
2. 材料不足时，在当前位置进入 `Waiting: MaterialsMissing`。
3. 材料足够时，寻找最近的已知、可达、compatible station。
4. 没有已知可达 compatible station、但仍有可达 frontier 时，按目标索取规则进入自动探索；station 和 frontier 都不可达时进入 `NoReachableTargetOrFrontier`。
5. 到达 station 后执行完整生产周期；每个周期原子结算后重新检查材料。

`station requirement` 为空的 handcraft recipe 在当前位置生产，不进行 station 索取。系统不得因为缺料而自动寻找材料、采集或购买。

## 生产材料不足

材料不足时：

1. 保留生产任务和已完成数量。
2. 角色原地进入 `等待条件`。
3. 显示缺少的材料或明确停止原因。
4. 不自动购买，不自动采集，不自动切换任务。
5. 只在库存发生变化事件时重新判断，不进行轮询。

条件恢复后，系统继续同一生产任务。新的生产周期仍在完成时一次性消耗材料。

## 强制战斗中断

- forced combat 暂停当前 motion leg 或 non-combat action progress，并物化精确交战位置。
- 战斗结束后，若唯一 `TaskIntent`、action target 和全部 prerequisites 未改变，则从精确交战位置继续剩余 path/action。
- `TaskIntent` 被替换或取消时，取消旧 movement/action execution。
- 装备变化时，取消旧 movement execution 或 non-combat action cycle，并按新 prerequisites 重新计算路径、目标与唯一活动任务。
- 被取消的周期不产出、不消耗材料，也不发 XP。
- 加载后可以从保存的 fixed-point motion/action progress 恢复，或根据相同权威输入稳定重算；两种方式不能改变结算结果。

## 目标索取与自动探索

目标筛选、路径成本和迷雾规则见[探索与目标索取](exploration.md)。没有合格目标时，任务进入 `自动探索`；发现合格目标后立即退出自动探索并重新规划。

资源耗尽或敌人死亡后，在内容规则规定的时间重生。重生前不属于有效目标。系统不会为了原地等待重生而放弃已规定的自动探索。

## 战斗、死亡和离线

- 强制战斗是执行状态，不是任务；开始战斗不替换活动任务。
- 角色死亡后保留活动任务和已完成数量，但取消当前 movement execution 或 non-combat action cycle。
- Accepted 首轮 `60s` 后在精确死亡位置复活，并从头重新评估最新有效 `TaskIntent`、目标和路径。Accepted 首轮 `5s RevivalGrace` 只阻止非狩猎目标敌人的强制遭遇，不暂停或替换任务。
- 离线推进使用相同任务状态机；有数量任务完成后，剩余离线时间原地待机。

战斗与复活见[战斗与潜行](combat-stealth.md)，离线预算与报告见[离线推进](offline-progression.md)。

`Lead` 只有在玩家主动预填并提交探索任务后，才按普通任务替换规则创建探索 `TaskIntent`；见[碎片叙事与线索簿](narrative-cluebook.md#自动执行与玩家控制)。

## 验收标准

- 同时最多存在一个活动任务，没有隐藏队列。
- 未指定任务类别和目标时，系统不会自行选择成长方向。
- 数量留空的适用任务持续执行，直到取消或替换。
- 达到或超过数量后保留完整实际产物，并原地待机。
- 替换或取消丢弃旧任务计数，但不回滚永久结算。
- 战斗中 `SetTask`/`CancelTask` 立即原子更新唯一 `TaskIntent`，不存在 pending intent 或隐藏 queue。
- 取消或替换任务不能逃离已经触发的战斗。
- 战斗和死亡不重置仍有效任务的计数。
- forced combat 暂停 movement/non-combat progress；只有任务和 prerequisites 未变时才继续。
- 玩家死亡会取消而不是暂停未完成 motion/action；自由向量协议规定在精确死亡 `WorldPoint` 复活后从头重评任务。
- 取消未完成生产周期不消耗材料、不产生输出或经验。
- 生产缺料保留任务，并只在库存变化时重新判断。
- production task 按 recipe/level/equipment → materials → compatible station → action 的固定顺序评估。
- 当前执行状态始终能追溯到固定优先级和一个有效任务意图。
