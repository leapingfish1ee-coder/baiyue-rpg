# 战斗、潜行与死亡

状态：已确认产品设计基线。

> 发现概率上下限和复活等待时间是 Accepted 首轮平衡基线，不是已实现事实。调整这些数值必须形成明确的游戏规则版本和平衡记录，不得修改地形 `GENERATOR_VERSION`。

## 战斗定位

战斗是世界中的连续执行状态，不是任务或独立模式。开始战斗不会替换当前 `TaskIntent`。

- 与当前狩猎 `TaskIntent` 指定 archetype 匹配的敌人进入有效接触范围后强制开战。
- 其他敌人通过遭遇判定发现角色后强制开战。
- 已触发的强制战斗优先于任务、自动探索和待机。
- 战斗中 `SetTask`/`CancelTask` 立即原子替换或清除唯一 `TaskIntent`，但不能逃离当前战斗。`CombatState` 继续；战斗结束或复活后执行当时唯一的任务意图。

## 确定性遭遇判定

角色 motion 首次与敌人 detection circle 相交时，只进行一次遭遇判定。判定不得逐帧重复。[自由向量移动协议](movement-navigation-protocol.md#敌人检测的毫秒量化)把 T1/T2 detection radius 分别定为 `2/3 tiles`，并用整数毫秒 `(t-1,t]` swept-segment squared-distance 触发；同毫秒多敌按 `encounter_instance_id`。几何语义已 Accepted，半径是 Accepted 首轮平衡基线。

敌人身份分为：

- `placement_id`：content placement 的固定位置或巢点标识，跨重生稳定；
- `spawn_cycle`：每次有效重生单调加 `1`，持久化在 mutated entity state；
- `encounter_instance_id = placement_id + spawn_cycle`：一次生成周期内的遭遇身份。

地图知识、目标位置和 `next_available_time` 使用 `placement_id`。潜行一次性判定、潜行 XP 去重和 combat RNG 使用 `encounter_instance_id`。同一巢点进入新 `spawn_cycle` 后形成新的 encounter instance，可以再次进行一次有效潜行结算。

判定输入至少包括：

- `encounter_instance_id`；
- 敌人感知；
- 角色永久 `潜行` 等级；
- 当前装备提供的潜行效果；
- 游戏规则版本和稳定事件随机流标识。

结果必须可复现，并与帧率、chunk/任务访问顺序和地形生成随机流无关。游戏事件随机性与地形生成随机性必须使用分离的版本和随机域。

发现概率必须：

- 随敌人感知单调上升；
- 随角色潜行能力单调下降；
- 限制在 `5%–95%`。该区间是首轮平衡基线。

同一 `encounter_instance_id` 最多进行一次遭遇判定。离开再进入不会重复判定；只有敌人有效重生并增加 `spawn_cycle` 后，才能形成新的 encounter instance。

当前狩猎目标不进行避战判定；进入有效接触范围后直接强制开战。

自由向量移动协议进一步规定：成功潜行后，同一 `encounter_instance_id` 不再强制该角色战斗，直到敌人死亡并进入新 `spawn_cycle`。敌人在角色已处 detection circle 内复活时，在 respawn event 立即评估。

## 潜行经验

潜行经验只在角色完整通过一次有效非狩猎目标敌人威胁区且未被发现后结算。

- 同一 `encounter_instance_id` 最多结算一次潜行成功。
- 没有威胁的经过不结算。
- 被发现并进入战斗不结算。
- 狩猎目标不结算潜行成功。
- 移动、待机、失败、受伤和死亡均不直接结算潜行经验。

## 狩猎任务

- 狩猎必须指定 enemy archetype，并可指定击杀数量。
- 任何与当前狩猎 archetype 匹配、进入有效接触范围的敌人都视为主动狩猎目标，跳过避战判定并强制开战。
- 非目标敌人发现角色后仍可强制战斗。
- 非目标敌人击杀提供正常经验和掉落，但不增加狩猎数量。
- 只有目标敌人的实际击杀增加狩猎计数。
- 达到或超过击杀数量后完成任务；未指定数量时持续狩猎。

多个敌人在同一整数 world time 触发时，不比较 sub-millisecond 交点，按 `encounter_instance_id` 选择当前一对一敌人。其余敌人不加入该场战斗。战斗结束后，对仍在范围内且本 `spawn_cycle` 尚未完成 encounter check 的敌人按 `encounter_instance_id` 重新评估，可能连续进入下一场战斗。

## 击杀、经验与掉落

- 当前 `近战` 只在实际击杀时结算经验。
- 每次击杀最多生成一个经验包和一组掉落结算。
- 每次攻击、命中、受击、战斗时长和最后一击武器切换都不单独结算经验。
- 敌人强迫进入的战斗与主动狩猎使用相同经验和掉落规则。
- 未击杀、逃离或玩家死亡时，当前敌人不提供经验或掉落。
- 已完成击杀立即持久化；玩家随后死亡不会回滚经验、掉落或任务计数。

未来加入多种战斗方式时，经验包按各方式造成的有效伤害占比分配，过量伤害不计。完整规则见[技能成长](skill-progression.md#战斗经验包)。

## 连续恢复与限时效果

- 角色存活时，生命和其他可恢复战斗资源按世界时间连续自然恢复。
- 战斗、移动、待机或离线不改变存活角色的“持续恢复”语义。
- `RespawnState` 中的死亡角色不进行 HP 或其他战斗资源恢复。
- 属性和限时效果可以改变具体恢复速率。
- 增益和减益按世界时间到期。
- 切换任务不重置生命、可恢复资源或限时效果。
- 不存在死亡后的恢复期或冷却期状态。

具体战斗资源、恢复基线、战斗内恢复限制、属性公式和效果内容由战斗内容表声明；在线与离线必须使用相同语义。

## 死亡与复活

首轮死亡规则：

1. HP 到 `0` 时立即结束当前战斗。
2. 清除全部 temporary effects。
3. 导致死亡且仍存活的敌人恢复为满状态。
4. 物化精确死亡位置，并取消当前 motion/action；不保留进度，也不产生结算。
5. 玩家进入 `RespawnState`，保存精确死亡 `WorldPoint` 并等待 `60` 秒。`60` 秒是首轮平衡基线。
6. 死亡期间 world time 和其他 world events 继续，但 dead player 的 HP 和其他战斗资源不恢复。
7. 等待结束后，角色在精确死亡位置复活，并一次性设置基础 respawn resource baseline。
8. 保留装备、库存、永久技能、世界知识、当时唯一的 `TaskIntent` 及其已完成数量。
9. 复活后从头重新评估任务、目标和路径；没有任务时待机。

狩猎已完成击杀数不重置。敌人恢复满状态防止通过反复死亡累积伤害。

首个端到端版本不设置营地传送、尸体跑、物品或货币掉落、经验损失、装备耐久损失或其他死亡惩罚。死亡成本只有复活等待期间不能行动。

自由向量移动协议把复活资源基线具体化为 `max_hp` 和其他首版战斗资源默认值，并规定 `5s RevivalGrace`：非狩猎目标敌人不能在 grace 期间强制遭遇；主动狩猎或主动进入战斗会立即结束 grace。它不是 buff/debuff，不可叠加或修改。`5s` 是 Accepted 首轮平衡基线。

## 离线一致性

离线推进使用相同遭遇判定、战斗、恢复、效果到期、死亡和复活规则。相同初始状态与有效经过时间必须产生语义等价结果；离线批处理不能改变侦测次数、击杀结算或敌人死亡后的状态。

离线上限和回归报告见[离线推进](offline-progression.md)。

## 首个端到端版本排除项

- 地下城；
- 多人战斗和队伍；
- 自动消耗品；
- 逃跑策略；
- 战斗技能训练焦点；
- 尚未发布的远程或魔法战斗方式。

## 验收标准

- 同一 `encounter_instance_id` 不会因帧数、离开再进入或停留时间重复判定；新 `spawn_cycle` 可以形成新判定。
- 发现概率对敌人感知和玩家潜行能力保持规定的单调关系，并遵守首轮上下限。
- 所有遭遇随机结果可复现，且不使用地形生成随机流。
- 当前狩猎目标不进行避战判定，也不提供潜行成功经验。
- 非目标敌人击杀不增加狩猎计数，但正常结算经验和掉落。
- 一次击杀最多生成一个经验包；未击杀、逃离或死亡不结算。
- 战斗中取消或替换任务不会结束战斗。
- 战斗中任务更新立即作用于唯一 `TaskIntent`，不存在 pending task。
- 存活角色的恢复和限时效果在线/离线保持同一时间语义；死亡等待期间不恢复战斗资源。
- 死亡后等待首轮基线时间，在精确死亡位置复活。
- 复活清除临时效果、恢复资源基线，并保留永久状态和任务进度。
- 死亡取消未完成 movement/action；复活后从头重评任务和路径。
- 致死敌人恢复满状态；已结算击杀不回滚。
- 首版死亡不造成物品、货币、经验或耐久损失。
- Accepted `RevivalGrace` 在线、离线和 reload 使用相同 world-time 截止点，且不能阻止主动狩猎。
