# 需求索引

本目录记录已确认需求、首个切片规范、验收边界和未来范围问题。当前实现状态见[当前状态](../product/current-state.md)；Accepted 表示可以进入实现，不表示已经实现。

## 状态

- **已确认产品设计基线**：可用于内容设计、实现拆分和验收。
- **Accepted 首轮平衡基线**：已确认的初始数值；不是已实现事实，可通过显式、版本化的平衡决策调整。
- **Proposed**：等待负责人确认；只能用于评审，不能作为实现或验收基线。
- **待内容表**：机制已确认，但具体目标、配方、敌人、经验值或属性需由版本化内容表提供。
- **排除**：不进入首个端到端版本，不得预留空 UI 或空系统。

## 术语

| 术语 | 定义 |
|---|---|
| 活动任务 | 玩家当前唯一的高层意图。系统同时只保留一个任务实例。 |
| `TaskIntent` | 当前唯一任务的类别、目标、可选数量、已完成数量和创建时间；表达玩家决定，不存在 pending intent。 |
| `ExecutionState` | 系统当前执行状态；可因战斗、死亡或自动探索变化，但不能静默改写 `TaskIntent`。 |
| 自动探索 | 为当前任务寻找新目标的执行状态，不是新任务。 |
| 已知区域 | 玩家世界状态中已经揭露、可用于规划的地图范围。 |
| 当前有效目标 | 已知、类型匹配、状态有效且可达，允许任务系统索取的目标。 |
| 特殊发现 | 地标、资源类型、敌人类型或叙事线索的首次发现记录。 |
| 待机 | 不主动移动或执行行动，并向玩家报告原因。 |
| 有效结算 | 满足对应技能成功条件的一次永久结果；移动、待机、失败、受伤和死亡不属于有效结算。 |
| 技能等级 | `1–100` 的永久基础等级；该范围是首轮平衡基线。 |
| 内容准入 | 目标、配方、工具、装备、区域或行动声明的永久基础等级要求；装备和临时效果不能绕过。 |
| 主要里程碑 | 每 `10` 级的技能节点；间隔是首轮平衡基线，具体内容由内容表声明。 |
| 软专精 | 由时间投入、当前任务和可更换装备形成的当前效率倾向，不锁定长期成长范围。 |
| 经验包 | 一次击杀生成的唯一战斗经验总量；当前近战版本全部结算到 `近战`。 |
| 威胁区 | 敌人检测范围对应的一次有效通过区间；完整通过且未被发现才结算潜行经验。 |
| 死亡位置复活 | 角色等待 Accepted 首轮 `60s` 后，在精确死亡 `WorldPoint` 设置 respawn resource baseline。 |
| 世界时间 | 在线和离线共用的恢复、效果到期、重生和复活计时语义。 |
| 目标熟练度 | 后期条件式系统，只改善对应具体目标；不进入首个端到端版本。 |
| `item_id` | 物品内容定义的稳定标识；同一 ID 只有一组属性。 |
| 谜题线 | `Thread` 的中文 UI 术语；围绕一个核心问题组织叙事知识。 |
| 事实 | `Fact` 的中文 UI 术语；一次发现后永久记录的最小信息单元。 |
| 关系 | `Relation` 的中文 UI 术语；连接两个已知事实并说明关联。 |
| 推论 | `Insight` 的中文 UI 术语；由一组已知事实生成，并必须显示依据。 |
| 线索 | `Lead` 的中文 UI 术语；推论产生的可行动方向，不自动创建任务。 |
| 发现事件 | `DiscoveryEvent` 的中文 UI 术语；使一个事实首次变为 known 的玩法事件。 |
| `placement_id` | content placement 的固定位置或巢点 ID；跨重生稳定，用于地图知识和可用时间。 |
| `spawn_cycle` | placement 每次有效重生后单调加 `1` 的持久化序号。 |
| `encounter_instance_id` | `placement_id + spawn_cycle` 构成的一次生成身份；用于遭遇、潜行 XP 和 combat RNG。 |
| `WorldPoint` | 自由向量协议中的权威二维位置；`x/y` 是整数 nav units，通过 canonical decimal strings 跨协议和存档传递。 |
| `routeCost` | weighted Theta* 按已揭示 terrain 与精确整数/有理数规则计算的路线成本；“最近”以该版本 planner 的最低成本为准。 |
| `RevivalGrace` | Accepted 首轮 `5s` 系统状态；只阻止非狩猎目标敌人强制遭遇，不是 buff、无敌或战后恢复期。 |

## 首个端到端版本

必须包含：

- `探索`、`潜行`、`采集`、`伐木`、`采矿`、`锻造`、`工艺`、`近战`；
- `探索`、`采集`、`伐木`、`采矿`、`生产`、`狩猎` 六类任务；
- 单任务状态机、迷雾和自动探索；
- 强制战斗、击杀结算、自然恢复、死亡与复活；
- 离线推进；
- 技能、任务、地图、战斗和离线 UI。

明确排除：手动角色移动、任务队列、职业、转职、技能点、天赋树、洗点、训练焦点、目标熟练度、远程、魔法、烹饪、炼金、捕鱼、地下城、多人、市场、自动购买、自动换装、自动消耗品、库存容量、装备耐久、战后恢复期和冷却期。

## 跨需求约束

1. 玩家决定任务类别和目标；系统只负责索取目标、寻路、执行和处理中断。
2. `SetTask`/`CancelTask` 立即原子更新唯一 `TaskIntent`；战斗是更高优先级 interrupt，不产生 pending task。
3. 同时只有一个活动任务，不设计队列。
4. 经验只来自有效结算；额外产量不增加单次基础经验。
5. 迷雾后目标不可读取；最近目标按可达路径成本确定。
6. 游戏事件随机性与地形生成随机性分离，且所有结果可复现。
7. 在线和离线使用同一语义；批处理差异不能变成结果差异。
8. 地形 generator version、游戏规则版本和存档 schema 版本分离。
9. UI 必须解释当前玩家意图、执行状态和等待/停止原因。
10. 自由向量协议规定 forced combat 在整数 world time 物化精确位置并暂停 motion/action；任务、装备或 prerequisites 变化会取消旧执行且不结算。
11. 死亡取消未完成 motion/action；等待期间推进 world time，但 dead player 不恢复 HP/resource；角色在精确死亡 `WorldPoint` 复活，并从头重评任务与路径。
12. quantity overflow 在事务前拒绝整次结算并暂停模拟，不能丢弃或部分提交。
13. 首版只有自动自由向量移动，不提供 WASD、摇杆或点击地面即时控制角色；renderer 浮点插值没有 gameplay 语义。

## 实现与内容工作

稳定 ID grammar、完整配方输出、正式世界观文案、视觉 token、Worker/UI 字段、IndexedDB keyPath、导入错误分类、fixtures、benchmark、可复现模拟和试玩结果，均由对应 Accepted 规范的“实现、内容与验证工作”章节管理。它们必须在相关编码或验收前写入 docs，但不重新打开整体产品方向。

## 未来范围待决

以下事项只有负责人未来将其纳入新阶段后才进入需求设计；它们不阻塞首个切片实现：

- 远程、烹饪、炼金、捕鱼或魔法何时满足端到端加入条件；
- 内容规模达到阈值后是否加入目标熟练度；
- 是否引入手动角色移动、地下城、敌群/波次或战斗消耗品；
- 是否引入异步交互、市场或多人，以及相应服务器时间和经济权威。

当前不接受任务队列、容量/搬运、装备耐久、恢复期或冷却期；未来若改变，必须形成新的明确产品决策。

MVP/demo 阶段若负责人确认的新需求与本基线冲突，直接修改这些真源并删除旧规则，不增加兼容层或并行旧模式。

新增需求使用[需求模板](../templates/requirement.md)。
