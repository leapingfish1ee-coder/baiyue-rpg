## 被否决的成长模型

- 不采用 IdleOn 式职业锁定和多角色分工。该模型会把完整成长拆给多个角色，与单角色全技能目标冲突。
- 不采用 EVE 式现实时间被动训练。该模型会在没有有效玩法结算时授予成长，与经验来源契约冲突。
- 不采用永久职业、不可逆天赋或依赖洗点的专精。装备与当前任务已经提供可逆软专精。

外部产品事实和来源见[可比游戏研究](../research/comparable-games.md)；研究材料不拥有需求权威。

## 不可随意改变的产品语义

以下内容属于产品语义。变更需要负责人明确提出新需求，不能作为普通数值平衡或实现便利调整：

- 单角色可以学习全部已发布技能，不存在职业或永久互斥成长。
- 玩家决定任务类别和目标；自动系统只负责目标索取、寻路、执行和中断处理。
- 同时只有一个活动任务；任务意图和当前执行状态分离。
- 技能经验只来自有效结算；移动、待机、失败、受伤和死亡不直接提供经验。
- 额外产量增加物品与任务计数，但不增加单次基础经验。
- 战斗是世界连续状态，不是任务；强制战斗和死亡不替换任务。
- 迷雾后目标不可读取；目标按可达路径成本选择。
- 游戏事件随机性与地形生成随机性分离，结果不依赖帧率或访问顺序。
- 在线和离线使用同一任务、恢复、效果、战斗、死亡和完成语义。
- 地形 generator version、游戏规则版本和存档 schema 版本相互独立。

## 可调整的首轮平衡参数

首轮平衡参数属于已确认初值，不是产品永久语义，也不是已实现事实。至少包括：

- 升级曲线 `round(100 × 1.12^(L-1))`；
- 死亡后等待 `60` 秒复活；
- 单次离线推进上限 `168` 小时；
- 技能等级上限、主要里程碑间隔、技能速度加成和持续时间下限；
- 遭遇发现概率上下限；
- 后续目标熟练度的引入阈值、等级范围和里程碑。

这些数值在对应需求中逐项标记为“首轮平衡基线”。调整时必须：

1. 说明调整依据和受影响体验。
2. 更新对应需求、内容表、测试 fixture 和游戏规则版本决定。
3. 检查是否影响存档 schema 或已有稳定存档。
4. 不修改地形 `GENERATOR_VERSION`，除非地形 bytes 本身发生变化。

## MVP/demo 变更政策

MVP/demo 阶段不维护旧产品规则兼容。若负责人确认的新需求与本基线冲突：

1. 直接修订需求真源。
2. 删除被替代的旧规则、旧候选和过时路径。
3. 更新本记录或以新 Decision Record 解释仍有长期价值的取舍。
4. 不增加兼容模式、迁移层、旧规则开关或双轨实现。

该政策不降低变更透明度。生成 bytes、游戏规则版本和存档 schema 仍必须分别作出明确决定。

## 后果

- 内容、UI、玩法状态和离线模拟拥有共同验收基线。
- 工程实现不能自行把平衡参数升级为永久协议。
- 数值调整比产品语义调整成本低，但仍需版本和验证证据。
- 竞品分析继续只提供研究依据，不拥有产品规范权威。
